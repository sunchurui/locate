# 2026-11-02：统一改为总体匹配计数汇总

用户明确要求把全部主结果改成根因审计表E版本。当前协议为
`rex_matching_global_endpoint_micro_v1`。旧作者指标与AP均保留为历史记录，
不再作为当前主结果；没有重新训练或重新生成预测。

## 原作者问题与项目实现的边界

1. 固定版本原作者C++精确率提取变量未按类别/IoU重置，是已复现的实现缺陷。
2. 原作者safe_mean跳过零值、从插值PR曲线提取精确率，是原代码实际采用的
   汇总定义，会放大小子集的乐观结果；不能当成我们外层新增的逻辑。
3. 类别宏平均给每个类别相同权重，属于一种合理统计目标，不是代码bug。
   但它不是把所有目标的匹配数量相加，所以本项目按用户决定改为micro汇总。
4. 本项目外层转换已与未改动的官方转换器/CLI核对：完全相同转换后输入，
   六组P/R原始数组逐元素相等。外层不是旧7.78点差距的主要原因。
5. 先前使用人为排序AP和自定义AP_set是项目曾采用的错误口径，已经撤回。
   不能把这些历史问题与此次定位出的上游缺陷混为一谈。

## 新定义与直观例子

每个IoU阈值0.50、0.55、…、0.95，沿用Rex逐图片逐类别原生匹配。
在全体图片和类别上分别相加TP、FP、FN，再计算P、R、F1。

例如最终总计50个正确框、10个误检、50个漏检：
P=50/60=83.33%，R=50/100=50%，F1=100/160=62.50%。
将图片分成两份再相加计数，应得到完全相同的结果；不能直接平均两份F1。
没有预测对的类别仍贡献FN；没有GT的类别若输出框仍贡献FP。

meanIoU先平均十个阈值的P、R，再取调和均值，与审计表E完全一致；
不等同于十个F1的算术平均。逐阈值计数和分数全部保存。

原生crowd/ignore、同分匹配和maxDets100/图片/类别保留，不做PR曲线汇总或
跨图片置信度排名。新汇总不保证任意256张都与5000张接近，也不保证原生
贪心匹配对图片内部框顺序不敏感。不能把本项目指标冒称原论文原始F1。

- 新构建在完整5000/固定256上的全部逐类别逐IoU TP/FP/GT数组，与根因审计
  导出的原匹配计数逐项相等。没有更换匹配算法。
- 256拆成两个128后，各IoU下TP/FP/GT/FN可加性通过。

- 55组保存结果统一重算，覆盖上一版全部53组来源，新增2组正在生成的
  全量评测快照标为partial；7个推理分片、4条SFT验证曲线同步迁移。
- CPU构建207836、验证207839、全量重算207844、展示迁移207851均完成。
- 两个已在生成的作业206048/207732保持运行。为其增加完成后的CPU重算
  207846/207847及展示刷新207852/207853，避免进程中已加载的旧代码留下
  旧主指标。它们是依赖作业，不是恢复周期自动检查。
- 模型、数据、检查点和旧预测全部保留。旧数值存档，主输出micro_metrics.json，
  set_metrics.json是兼容副本。原作者计分保存在legacy_rex_metrics.py。
